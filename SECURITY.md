# Security policy

## Reporting a vulnerability

Please use [GitHub's private vulnerability reporting form](https://github.com/DejavuMoe/Pail/security/advisories/new) for suspected security issues in Pail. Do not disclose exploitable details in public issues or pull requests.

Include the affected Pail version or commit, operating system and architecture, reproduction steps, expected impact, and a minimal example with dummy credentials. Never include live access keys, session tokens, vault passwords or private bucket contents. If credentials were exposed, revoke or rotate them with the provider.

Please check the [latest stable release](https://github.com/DejavuMoe/Pail/releases/latest) when possible. Reports affecting `master` are also welcome. Response and fix times depend on severity and maintainer availability; no response deadline or bounty is promised.

GitHub hosts private reports and release assets; Forgejo remains the source repository. Coordinate disclosure privately. Maintainers develop and validate fixes through Forgejo and publish an advisory when appropriate.

## 安全漏洞报告

发现 Pail 的疑似安全漏洞时，请使用 [GitHub 私密漏洞报告表单](https://github.com/DejavuMoe/Pail/security/advisories/new)，不要在公开 Issue 或 PR 中披露可被利用的细节。

请提供受影响的 Pail 版本或提交、操作系统与架构、复现步骤、预期影响，以及使用虚构凭据的最小示例。不要提交真实访问密钥、会话令牌、保险库密码或私有桶内容。凭据如已泄露，请在服务提供方撤销或轮换。

条件允许时，请先检查[最新稳定版](https://github.com/DejavuMoe/Pail/releases/latest)是否仍受影响；也欢迎报告 `master` 上的问题。响应与修复时间取决于严重程度和维护者的可用时间，不承诺处理期限或漏洞奖金。

GitHub 承载私密报告和发布产物，Forgejo 仍是源代码主仓库。请私下协调披露；维护者通过 Forgejo 开发并验证修复，在适当时发布安全公告。
