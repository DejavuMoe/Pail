# 同步任务与上传规则

同步任务让本地文件夹和存储桶前缀按一个方向保持一致，并在改动任何内容之前先给出计划。上传规则按存储桶和对象键，为上传的对象设置标头、存储类别、加密和压缩。

## 同步任务

从侧栏 **工具** 分组里打开 **同步任务**，也可以从命令面板打开，或用 `pail-desktop --tool sync` 启动应用。任务保存在 Pail 的配置里，之后可以在应用或命令行里再次运行。

### 创建任务

1. 点击 **新建任务**；已有任务时点击 **新建**。
2. 填写 **任务名称**。留空时以本地文件夹的名称命名。
3. 选择 **方向**，用 **选择…** 指定 **本地文件夹**，再选择 **账户**、**存储桶**，可选填 **前缀**，例如 `photos/`。
4. 选择 **模式** 和 **比较方式**，需要时填写 **排除**。
5. 点击 **保存**。

**移除任务** 只删除保存的任务，本地文件和对象都保持原样。

### 方向与模式

同步只朝一个方向进行。**上传** 让存储桶前缀跟随本地文件夹；**下载** 让本地文件夹跟随存储桶前缀。源端永远不会被修改。

| 模式 | 作用 |
| --- | --- |
| **仅新增** | 只复制目标位置缺少的文件。 |
| **新增和变更** | 还会按比较方式替换有差异的文件。 |
| **镜像** | 还会删除目标位置有、源端没有的文件。 |

> **镜像** 会删除目标位置多出的文件。请先预览任务，核对计划里的删除项。

### 比较方式

| 比较方式 | 文件在以下情况下视为有变更 |
| --- | --- |
| **大小和时间** | 大小或修改时间不同。下载时只有对象更新，才会替换本地文件。 |
| **大小** | 大小不同。 |
| **校验和** | 它的 SHA-256 与之前同步时保存在对象上的值不同。 |

每种方式都有局限：

- **大小和时间** 可能漏掉不改变文件大小的修改。
- **大小** 会漏掉所有不改变文件大小的修改。
- **校验和** 依赖 Pail 在同步时保存在对象上的 SHA-256。没有这个值的对象（例如用其他工具上传的文件）都视为有变更，会重新传输。

### 排除规则

**排除** 每行填写一个模式，例如 `*.tmp`。模式与相对于任务文件夹的完整路径匹配，路径用 `/` 分隔：

- `*` 匹配任意字符，包括 `/`；
- `?` 正好匹配一个字符；
- 以 `/` 结尾的模式，例如 `cache/`，排除这个文件夹及其中的全部内容。

被排除的文件在两端都会跳过，所以镜像永远不会删除它们。

本地文件夹里的符号链接不会被跟随，在计划中显示为已跳过。

### 预览并运行

**预览** 读取两端，列出同步将要执行的操作，不做任何改动。

- 列表上方的计数显示上传、下载、删除和跳过的文件数。
- 筛选可在 **全部**、**变更**、**删除** 和 **已跳过** 之间切换。
- 每行显示 **路径**、**原因** 和大小。

之后 **运行同步** 严格执行预览中的操作。预览之后又有变化的文件不会被覆盖。修改任务会清除预览。

没有需要执行的操作时，Pail 会直接说明。不含删除的同步立即开始。含删除的同步会先询问 **运行同步？**，并显示任务、本地文件夹、远程前缀、上传数、下载数、删除数和总大小。

### 删除与回收站

上传方向的镜像会删除存储桶里的对象。下载方向的镜像不会直接删除本地文件，而是把它们移到回收站（Windows 的回收站，macOS 和 Linux 的废纸篓）。

在做下载镜像之前，请先备份重要文件。

### 在命令行运行已保存的任务

`pail sync` 可以直接同步，也可以运行已保存的任务。方向由参数顺序决定：本地文件夹在前为上传，存储桶地址在前为下载。

```sh
pail sync ./photos s3://my-bucket/photos/ --dry-run
pail sync ./photos s3://my-bucket/photos/ --mode mirror --exclude "*.tmp"
pail sync s3://my-bucket/photos/ ./photos --compare checksum
pail sync --job Photos --dry-run
pail sync --job Photos
```

| 参数 | 取值 |
| --- | --- |
| `--mode` | `new`、`new_changed`（默认）或 `mirror`。 |
| `--compare` | `size_time`（默认）、`size` 或 `checksum`。 |
| `--exclude` | 一个模式。可重复使用以指定多个模式。 |
| `--no-rules` | 上传时不应用上传规则。 |
| `--dry-run` | 输出计划，不做改动，不询问，以退出码 0 结束。 |

含删除的同步会先输出范围并询问 `Proceed? [y/N]`。没有终端时，除非加上 `--yes`，否则以退出码 2 结束。`--job NAME` 使用任务自己的账户，除非另外给出 `--account`。

`pail sync job ls` 列出已保存的任务。`pail sync job add NAME LOCAL s3://bucket/prefix/` 保存上传任务，`pail sync job add NAME s3://bucket/prefix/ LOCAL` 保存下载任务；两者接受相同的参数，本地文件夹必须已经存在。`pail sync job rm NAME` 在确认后移除任务。详见命令行参考的 [命令详解](../cli.zh-CN.md#command-details)、[管理](../cli.zh-CN.md#administration) 和 [确认](../cli.zh-CN.md#confirmation)。

## 上传规则

从侧栏 **工具** 分组里打开 **上传规则**，也可以从命令面板打开，或用 `pail-desktop --tool rules` 启动应用。规则作用于应用里的上传、`pail cp` 和 `pail sync`。

点击 **添加规则** 新建规则。**复制规则**、**移除规则**、**上移规则** 和 **下移规则** 作用于选中的规则；每条规则都有一个开关，可以停用而不删除。点击 **保存** 保留修改，点击 **还原** 放弃修改。

规则从上到下检查。对每一类设置（标头和元数据、存储类别、加密、压缩），第一条匹配且设置了该项的规则生效。具体的规则应放在通用规则上面。

### 匹配存储桶和对象键

| 字段 | 匹配的内容 |
| --- | --- |
| **名称** | 只是列表里显示的标签。 |
| **存储桶匹配** | 存储桶名称，例如 `media-*`。`*` 匹配任意字符，`?` 正好匹配一个字符。留空匹配所有存储桶。 |
| **对象键匹配** | 完整的对象键。`*` 匹配任意字符，包括 `/`，所以 `images/*.png` 也匹配 `images/a/b.png`。留空匹配所有对象键。 |

两种匹配都区分大小写。

### 标头与元数据

在 **标头** 下，**添加标头** 可以设置 Cache-Control、Content-Disposition、Content-Encoding、Content-Language、Content-Type 或 Expires。这里设置的 Content-Type 会替代 MIME 类型表里的值，ZIP 输出除外。

在 **元数据** 下，**添加元数据** 为对象添加用户元数据。元数据名称以小写形式保存。

### 存储类别与加密

**存储** 下的 **存储类别** 可选 **默认**（由服务端决定，通常是 STANDARD），STANDARD、STANDARD_IA、ONEZONE_IA、INTELLIGENT_TIERING、GLACIER_IR、GLACIER、DEEP_ARCHIVE、REDUCED_REDUNDANCY 之一，或 **其他…**，用于服务商自己定义的存储类别名称。

**加密** 部分可选：

- **无**；
- AES256，使用 S3 管理的密钥；
- aws:kms，可选填 **KMS 密钥 ID**；
- SSE-C，使用你自己持有的密钥。它的 **密钥引用** 指向一个保存的机密，其中是 base64 编码的 32 字节密钥，而且账户的端点必须使用 https。

### 压缩

**压缩** 部分可选：

- **无**；
- GZIP，保留对象键，并设置 `Content-Encoding: gzip`；
- ZIP 或 AES-256 ZIP，上传一个 `.zip` 对象，并在对象键后加上 `.zip`。

不要在同一条规则里同时使用 GZIP 或 ZIP 和 Content-Encoding 标头。

**级别** 可选 **默认**、**仅哈夫曼编码**、**0（仅存储）** 或 1 到 9；9 压缩率最高，速度最慢。对于 AES-256 ZIP，**密码** 填写一个保存的机密的名称，其中是 ZIP 密码；规则只保存这个名称。**管理机密…** 打开 **机密** 对话框，可以在那里添加或修改它。

ZIP 文件保留文件自己的修改日期。

如果代理会解压 gzip 响应，gzip 编码对象的大小就会与服务端报告的不一致。这时 Pail 会拒绝下载，不写入任何文件。

### 测试规则

填写 **测试存储桶** 和 **测试对象键**，即可查看规则会对这次上传应用哪些设置。测试包含尚未保存的修改，此时结果标为 **含未保存修改**。

### 命令行中的规则

`pail cp` 和 `pail sync` 应用与应用程序相同的规则。`pail sync --no-rules` 上传时不应用规则。规则用到机密（例如 ZIP 密码）时，请先解锁加密保险库。

`pail cp --decode` 加上 `gzip`、`zip` 或 `auto`，在下载时解码压缩过的对象：

```sh
pail cp s3://my-bucket/logs/app.log ./app.log --decode gzip
```

详见命令行参考的 [命令详解](../cli.zh-CN.md#command-details) 和 [加密保险库](../cli.zh-CN.md#encrypted-vault)。
