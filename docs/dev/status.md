# Pail 验证状态

本文记录每个功能现在被验证到什么程度，不是工作日志。每一项分四层记录，彼此不能替代：

- **API**：`internal/app`（或 `internal/storage` 等）里有对应的导出函数。
- **界面**：`cmd/pail-desktop` 里有入口（命令、菜单、对话框或工具页）。界面按钮存在不代表它对着真实服务端点过。
- **协议测试**：针对 `internal/s3test`（内存 S3，经真实 SDK 驱动）或 `httptest` 的命名测试。
- **真实端到端**：针对真实服务端或真机的测试，分三类：MinIO（`integration/app_*_test.go`）、VersityGW（`integration/ext_*_test.go`，经 Cloudflare，只写唯一前缀并清理），以及所有者手动完成的真机与真实云服务验证（见“验证环境”表中的 macOS、Amazon S3、Cloudflare R2、Wasabi）。

标记：✅ 有证据，⚠️ 部分覆盖，❌ 没有，n/a 不适用。

更名为 Pail 之后（2026-10-20）重跑了：Windows `gofmt`/`go vet`/`go test`、Linux `go vet` 与 `go test -race`（全部包）、六个目标的发布构建与包内容检查、MinIO 固定版本套件、`--demo` 冒烟与 README 截图重新生成。VersityGW 外部套件和 MinIO 最新上游套件在更名后尚未重跑，上表这两行的结果来自更名前的同一份功能代码。

VersityGW 已确认的行为：PutObject 与 CompleteMultipartUpload 遵守 `If-None-Match` / `If-Match`，CopyObject 忽略 `If-None-Match`；五种 checksum 与对象标签可用；读取对象 ACL 返回 NotImplemented（应用报 Unsupported）；存储类别与 SSE 被静默忽略（应用把这些项报为 failed）；未开启版本控制；Cloudflare 会解压 gzip 对象，HEAD 与 GET 的大小不一致（应用拒绝发布这类下载）。

## 已知限制与未验证

- AWS 的 STS AssumeRole 与 CloudFront 没有在真实环境测试，只在 `httptest` 上验证。Amazon S3、Cloudflare R2、Wasabi 已手动测试可用。
- macOS `.app` 没有开发者签名、未公证；下载后首次启动需要执行 `xattr -dr com.apple.quarantine`。
- VersityGW 上的版本控制：服务端未开启，相关场景被跳过。
- 经 Cloudflare 的 gzip 对象：代理会解压，下载被拒绝（不会写出错误文件）。
- SSE-S3、SSE-KMS、SSE-C 成功路径：MinIO 没有配置 KMS，VersityGW 忽略加密；https 端点上的 SSE-C 成功路径从未运行。
- 超过 5 GiB 的对象经原地改写（存储类别、加密、属性）的分片复制路径：未验证。
- 本地镜像删除移入真实回收站：只验证了预览。
- 窗口内菜单（Windows 与 Linux）：只有 headless 测试与快照目视，没有在原生窗口里手动操作，也没有用读屏软件验证。macOS 的系统右键菜单与系统菜单栏：没有目视审阅。
- 界面动效：只有受控时钟的 headless 测试与快照目视，没有在任何原生窗口里观看过，流畅度、帧率与"减少动态效果"的系统设置都未在真实桌面上验证。
- 窗口拖动缩放时的布局抖动：应用侧的晚一帧回读和断点翻转已修，有 headless 回归测试。mygo v0.6.0 的 Direct3D 11 后端改为只重绘变化区域、`Present` 不再阻塞主线程，但缩放中的帧仍同步绘制；系统按钮与帧是否原子合成没有确认。v0.3.0 发布包已在 Windows 原生窗口拖动缩小、最大化和还原，稳定帧未见布局错乱；未采集拖动中的连续帧或做升级前后对比，因此仍不标记为解决。
- mygo v0.6.3 的库内改动未在原生窗口测量：Direct3D 11 上内容未变的帧改为等待显示器下一次刷新再继续，动画中不足一像素的变化不再连续重绘；超过 8 MB 的单段文字布局在不挤掉近期布局时也会缓存（上限 32 MB），减少重复排版但可能增加常驻内存。v0.3.2 发布包：Windows amd64 解压后 `pail version` 正常，原生窗口 `--demo` 启动并保持运行；Linux amd64 包在 WSL 解压后 `pail version` 与 `pail-desktop --version` 正常；CPU 占用与内存没有做前后对比。
- mygo v0.7.3（自 v0.6.3 升级）：导出 API 对 Pail 无删除或签名变化，Windows、Linux 构建与全部测试通过，macOS arm64 交叉编译通过（不代表真机）。Windows 原生窗口 `--demo` 在 2 倍缩放、960×600 下启动，`⋯` 菜单与主题子菜单可用键盘打开、切换并恢复。以下库内修复与 Pail 有关，但均未单独实机验证：Windows 缩放窗口时内容不再放大裁切、快速缩放的新边缘显示背景色而非黑色、隐藏标题栏不再出现强调色条、中日韩短标签不再被省略号截断；macOS 从原生界面点击打开的文件对话框能正常显示并等待、无文本框聚焦时 ⌘C/⌘V/⌘X/⌘A/⌘Z 窗口快捷键可触发、拖动区域移动窗口不再抖动、不再启动 AutoFill 辅助进程；Linux 从窗口自身控件关闭不再崩溃、快速轻点不再留下按住状态、两个应用同时启动不再损坏字体缓存；`Spinner` 等动画只重绘自身。破坏性变化不影响 Pail：页面的捏合缩放与滑动导航只作用于网页视图（Pail 不用），slug 与 DMG/安装包命名只作用于 `mygo build`（Pail 用 `tools/release`），macOS 子窗口（Pail 只有一个窗口）。
